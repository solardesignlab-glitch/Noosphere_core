# UCP MVP — инструкция для продолжения работы

## 1. Назначение документа

Этот документ — рабочая инструкция для команды, которая продолжает разработку проекта **UCP MVP / «Атмосфера»**.

Он фиксирует:

- текущее состояние проекта;
- архитектуру;
- порядок локального запуска;
- модель данных;
- роли пользователей;
- приоритеты разработки;
- отложенные задачи;
- правила безопасности;
- следующий этап работ.

Документ рассчитан на нового разработчика, аналитика или ИИ-агента, который подключается к проекту.

---

## 2. Краткое описание проекта

**UCP MVP** — прототип корпоративной платформы для управления клиентами, задачами, записями и внутренними процессами.

Проект построен на open-source CRM **EspoCRM** и разворачивается локально через Docker Compose.

Цель MVP — проверить ключевые сценарии:

- ведение клиентов;
- управление мастерами и услугами;
- создание и контроль записей;
- ролевой доступ сотрудников;
- базовая аналитика;
- кастомный интерфейс «Атмосфера».

Telegram-интеграция **отложена** и не входит в текущий рабочий контур MVP.

## 3. Текущий статус

| Компонент | Статус | Комментарий |
|---|---|---|
| Docker Compose | Работает | Локальная оркестрация сервисов |
| MariaDB | Работает | Основная база данных |
| Redis | Работает | Кэш, сессии, возможная основа для очередей |
| EspoCRM | Работает | Доступен на `http://localhost:8081` |
| Кастомный CSS «Атмосфера» | Подключён | `atmosfera.css` загружается |
| Модель данных | В настройке | `Appointment`, `Master`, `Service` созданы |
| Роли | В настройке | Owner, Administrator, Master, Marketer, Sales, API |
| Telegram-бот | Отложено | Не входит в текущий скоуп |
| Telegram-сервис | Отложено | Контейнер может присутствовать, но не настраивается |
| Уведомления | Отложено | Telegram-уведомления не реализованы |
| Маркетинг и продажи | В планировании | Структура лидов, кампаний и сделок |
| Аналитика | В планировании | Дашборды и KPI |

## 6. Требования к окружению

- Docker Engine 20.10 или новее.
- Docker Compose 2.0 или новее.
- Docker Desktop для Windows/macOS.
- Свободное место: минимум 2 ГБ.
- Порт `8081` должен быть свободен.
- Порт `3306` для MariaDB и `6379` для Redis должны быть открыты только при необходимости.

## 8. Порядок локального запуска

### 1. Открыть PowerShell

```powershell
cd C:\Projects\ucp-mvp
```

### 2. Проверить проект

```powershell
Get-ChildItem
Test-Path .env
```

Если `.env` отсутствует:

```powershell
Copy-Item .env.example .env
```

### 3. Запустить Docker Desktop

```powershell
Start-Process "C:\Program Files\Docker\Docker\Docker Desktop.exe"
Start-Sleep -Seconds 60
docker ps
```

### 4. Запустить проект

```powershell
docker compose up -d
```

### 5. Проверить контейнеры

```powershell
docker compose ps
```

### 6. Проверить логи

```powershell
docker compose logs --tail 30 espocrm
```

### 7. Открыть CRM

```powershell
Start-Process "http://localhost:8081"
```

### 8. Остановить Telegram, если он не нужен

```powershell
docker compose stop telegram
```

### 9. Очистить кэш после изменений

```powershell
docker compose exec espocrm php /var/www/html/command.php clear-cache
```

Затем в браузере:

```text
Ctrl + F5
```

## 10. Переменные окружения

`.env` не должен попадать в Git.

Минимальный набор переменных:

```env
DB_NAME=espocrm
DB_USER=espocrm
DB_PASSWORD=change_me_strong_password

ESPOCRM_ADMIN_USERNAME=admin
ESPOCRM_ADMIN_PASSWORD=change_me_admin_password

SITE_URL=http://localhost:8081

ESPOCRM_API_USERNAME=api_user
ESPOCRM_API_PASSWORD=change_me_api_password
```

Telegram-переменные на текущем этапе не настраиваются:

```env
TELEGRAM_BOT_TOKEN=not_used_yet
ADMIN_TELEGRAM_ID=not_used_yet
```

## 11. Модель данных

### Contact — клиент

| Поле | Тип | Назначение |
|---|---|---|
| Имя | Text | Имя клиента |
| Фамилия | Text | Фамилия клиента |
| Телефон | Phone | Контактный телефон |
| Email | Email | Электронная почта |
| Telegram ID | Text | Будущий идентификатор Telegram |
| Источник | Enum | Telegram, Instagram, Сайт, Рекомендация |
| Заметки | Text | Дополнительная информация |

### Master — мастер

| Поле | Тип | Назначение |
|---|---|---|
| Имя | Text | Имя мастера |
| Специализация | Text | Направление работы |
| Телефон | Phone | Контактный телефон |
| График работы | Text | Рабочие часы |
| Активен | Boolean | Доступен для записи |
| Заметки | Text | Дополнительная информация |

### Service — услуга

| Поле | Тип | Назначение |
|---|---|---|
| Название | Text | Название услуги |
| Категория | Text | Категория |
| Длительность | Integer | Длительность в минутах |
| Цена | Currency | Стоимость |
| Активна | Boolean | Доступна для записи |
| Описание | Text | Описание услуги |

### Appointment — запись

| Поле | Тип | Назначение |
|---|---|---|
| Клиент | Relation | Связь с Contact |
| Мастер | Relation | Связь с Master |
| Услуга | Relation | Связь с Service |
| Дата и время | DateTime | Начало записи |
| Длительность | Integer | Длительность в минутах |
| Статус | Enum | Жизненный цикл записи |
| Источник | Enum | Откуда пришла запись |
| Цена | Currency | Стоимость услуги |
| Предоплата | Currency | Сумма предоплаты |
| Заметки | Text | Комментарий |
| Telegram-чат ID | Text | Будущее поле для Telegram |

### Статусы записи

```text
new → confirmed → completed
new → cancelled
new → no_show
```

| Код | Название |
|---|---|
| `new` | Новая |
| `confirmed` | Подтверждена |
| `completed` | Завершена |
| `cancelled` | Отменена |
| `no_show` | Неявка |

## 12. Роли пользователей

| Роль | Доступ |
|---|---|
| Owner | Полный доступ: финансы, записи, клиенты, мастера, услуги, аналитика |
| Administrator | Записи, клиенты, мастера, услуги, расписание |
| Master | Только свои записи и свои клиенты |
| Marketer | Лиды, кампании, аналитика |
| Sales | Лиды, сделки, контакты |
| API | Только программный доступ через EspoCRM API |

Для будущей интеграции использовать отдельного пользователя `api_user`, а не администратора.

## 14. Ролевые интерфейсы

Принцип: одна CRM, но у каждой роли свой рабочий экран.

| Роль | Главный экран |
|---|---|
| Owner | Выручка, записи, загрузка, отмены, топ-услуги |
| Administrator | Записи на сегодня, свободные слоты, задачи |
| Master | Мои записи, следующий клиент, мои клиенты |
| Marketer | Лиды, кампании, источники, конверсия |
| Sales | Сделки, задачи, воронка, просроченные контакты |

### Дашборд владельца

- Выручка за сегодня, неделю, месяц.
- Количество записей.
- Новые клиенты.
- Загрузка мастеров.
- Средний чек.
- Отмены и неявки.
- Топ-услуги.
- Топ-мастера.

### Дашборд администратора

- Записи на сегодня.
- Свободные слоты.
- Ожидающие подтверждения.
- Клиенты, которые должны прийти.
- Отмены за сегодня.
- Задачи.
- Быстрое создание записи.

### Дашборд мастера

- Мои записи на сегодня.
- Следующий клиент.
- Мои клиенты.
- Мои услуги.
- История визитов.
- Заметки по клиенту.
- Моя выручка за день.

## 15. Маркетинг и продажи

### Структура

```text
Кампания / канал
  ↓
Лид
  ↓
Квалификация
  ↓
Сделка
  ↓
Клиент / Контракт
  ↓
Продление / допродажа
```

### Сущности

| Сущность | Назначение |
|---|---|
| Campaign | Источник трафика и маркетинговая активность |
| Lead | Заявка или потенциальный клиент |
| Opportunity | Сделка / продажа тарифа |
| Account | Компания-клиент |
| Contact | Контактное лицо |
| Document | КП, договор |
| Activity | Звонки, встречи, задачи |

### Этапы сделки

```text
Новая заявка
→ Квалификация
→ Демонстрация
→ Коммерческое предложение
→ Согласование
→ Оплата
→ Запуск
```

### Метрики

- количество лидов;
- количество сделок;
- выручка;
- стоимость лида;
- CAC;
- ROI;
- конверсия лид → сделка;
- средний чек;
- цикл сделки.

## 16. Безопасность

Обязательные правила:

- Не хранить секреты в коде.
- Не коммитить `.env` в Git.
- Использовать `.env.example` без реальных паролей.
- Создать отдельного API-пользователя.
- Ограничить права API-пользователя.
- Не публиковать порт MariaDB без необходимости.
- Настроить регулярный бэкап MariaDB.
- Использовать сильные пароли.
- Не использовать администратора для интеграций.

## 18. Приоритетный план работ

### Этап 1. Ядро CRM

1. Включить русский язык.
2. Настроить меню.
3. Переименовать сущности.
4. Проверить поля `Appointment`, `Master`, `Service`.
5. Настроить связи между сущностями.
6. Добавить недостающие поля.
7. Настроить статусы записи.

### Этап 2. Роли и данные

1. Создать роли.
2. Настроить права доступа.
3. Создать тестовые услуги.
4. Создать тестовых мастеров.
5. Создать тестовых клиентов.
6. Создать тестовые записи.

### Этап 3. Интерфейс

1. Проверить загрузку `atmosfera.css`.
2. Доработать панели, кнопки, таблицы и формы.
3. Настроить дашборд администратора.
4. Настроить дашборд мастера.
5. Настроить дашборд владельца.

### Этап 4. Маркетинг и продажи

1. Настроить кампании.
2. Настроить лиды.
3. Настроить сделки.
4. Настроить воронку.
5. Создать базовые отчёты.

### Этап 5. Telegram — после стабилизации CRM

1. Вернуть Telegram в скоуп.
2. Создать бота.
3. Настроить токены.
4. Реализовать сценарий записи.
5. Реализовать уведомления.
6. Протестировать полный цикл.
