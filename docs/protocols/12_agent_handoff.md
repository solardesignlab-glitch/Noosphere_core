# Передача задачи между агентами

## Назначение

Файл определяет, как передавать задачу, контекст и результат
между ролями и агентами проекта.

Передача нужна, чтобы следующий исполнитель не терял факты,
не повторял проверенные действия и не принимал гипотезы за факты.

## Когда нужна передача

Передача оформляется, если:

- задачу продолжает другой агент или роль;
- агент меняет роль внутри длинной задачи;
- задача приостановлена и будет продолжена позже;
- требуется независимое ревью;
- обнаружен конфликт источников или протоколов;
- задача выходит за текущую область и требует решения пользователя;
- выполнен важный этап: диагностика, изменение, миграция, релиз.

## Формат передачи

```text
ЗАДАЧА: ...
СТАТУС: Новая / В работе / Ожидает подтверждения / Заблокирована / Завершена
ЦЕЛЬ: ...
ЧТО СДЕЛАНО: ...
ЧТО НЕ СДЕЛАНО: ...
ПОДТВЕРЖДЁННЫЕ ФАКТЫ: ...
ИСТОЧНИКИ: ...
ГИПОТЕЗЫ: ...
НЕИЗВЕСТНО: ...
СЛЕДУЮЩИЙ ШАГ: ...
ОГРАНИЧЕНИЯ: ...
РИСКИ: ...
ПЛАН ОТКАТА: ...
КРИТЕРИЙ ЗАВЕРШЕНИЯ: ...
```

## Обязательные поля

| Поле | Что указывать |
|---|---|
| `ЗАДАЧА` | Краткое название задачи |
| `СТАТУС` | Текущий статус работы |
| `ЦЕЛЬ` | Ожидаемый проверяемый результат |
| `ЧТО СДЕЛАНО` | Фактически выполненные действия |
| `ЧТО НЕ СДЕЛАНО` | Предложенные, но не выполненные действия |
| `ПОДТВЕРЖДЁННЫЕ ФАКТЫ` | Только проверенные утверждения |
| `ИСТОЧНИКИ` | Файлы, команды, API, БД, логи, версии, даты |
| `ГИПОТЕЗЫ` | Предположения, требующие проверки |
| `НЕИЗВЕСТНО` | Пункты `Unknown` |
| `СЛЕДУЮЩИЙ ШАГ` | Конкретное следующее безопасное действие |
| `ОГРАНИЧЕНИЯ` | Скоуп, права, запреты, согласования |
| `РИСКИ` | Возможные последствия |
| `ПЛАН ОТКАТА` | Как вернуть систему в рабочее состояние |
| `КРИТЕРИЙ ЗАВЕРШЕНИЯ` | Как проверить, что задача выполнена |

## Источники истины

При передаче указывается домен данных
и основной источник истины согласно Закону 12.

| Тип данных | Основной источник истины |
|---|---|
| Клиент, услуга, запчасть, ресурс, актив, заказ | Ядро «Атмосферы» |
| Проводка, официальный счёт, налоговые данные | 1С клиента |
| Юридическая норма, её текст, редакция и статус | Официальный первоисточник |
| Публичная информация для клиента | Публичный API ядра |
| Действия и подтверждения AI | AI-журналы «Атмосферы» |
| Скоуп и статус функции | `scope_registry.md` |
| Архитектурное решение | `07_decision_log.md` |

## Правила передачи

- Отделять выполненные действия от предложенных.
- Не выдавать план за выполненную работу.
- Не выдавать гипотезу за подтверждённый факт.
- Указывать точный источник: путь, URL, команду, версию или дату.
- Указывать статус достоверности по `14_truth_sources.md`.
- Сохранять неизвестные пункты как `Unknown`.
- Не скрывать конфликты между источниками.
- Не передавать секреты, `.env`, токены и непубличные данные без необходимости.
- Не считать передачу задачи разрешением на расширение скоупа.
- Не считать передачу задачи подтверждением необратимого действия.

## Передача юридической задачи

Для юридической задачи дополнительно передаются:

- юрисдикция;
- тип, номер и название акта;
- редакция;
- дата вступления в силу;
- статус нормы;
- официальный первоисточник;
- дата проверки;
- дата следующей проверки;
- необходимость проверки юристом.

Юридическая норма превращается в требование продукта
только через протокол `КОМПЛАЕНС`.

AI не выдаёт юридическое заключение
и не рекомендует юридически значимое действие.

## Передача миграции данных

Для миграции данных из внешней системы, включая 1С,
дополнительно передаются:

- источник данных;
- сопоставление полей;
- правила трансформации;
- правила разрешения конфликтов;
- результат тестовой выгрузки;
- результат dry-run;
- план отката;
- статус подтверждения запуска.

Миграция не считается готовой к запуску
без протокола `МИГРАЦИЯ_ДАННЫХ`, dry-run и подтверждения.

## Приём задачи

Агент, принимающий задачу:

1. Проверяет статус в `scope_registry.md`.
2. Проверяет применимые законы, запреты и протоколы.
3. Проверяет указанные источники.
4. Отделяет факты от гипотез.
5. Фиксирует неизвестные пункты.
6. Уточняет противоречия до выполнения изменяющих действий.
7. Продолжает только в пределах переданных прав и скоупа.

Если данных недостаточно:

```text
UNKNOWN: недостаточно данных.
Чтобы продолжить, нужны: ...
```

## Завершение задачи

Задача считается завершённой, только если:

- выполнен заявленный объём в пределах скоупа;
- проведена проверка по критерию завершения;
- результаты проверок указаны;
- риски и ограничения переданы;
- план отката понятен;
- важные решения зафиксированы в `07_decision_log.md`;
- значимые ошибки зафиксированы в `08_error_log.md`;
- изменения сущностей отражены в `09_entity_registry.md`;
- изменения скоупа отражены в `scope_registry.md` после согласования.
