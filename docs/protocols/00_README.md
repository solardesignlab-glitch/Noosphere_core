# Библиотека протоколов проекта

Эта библиотека определяет, как мы работаем с ИИ-агентом, как принимаем решения и как безопасно меняем правила проекта.

## Приоритет документов

1. `01_laws.md` — законы проекта
2. `02_prohibitions.md` — запреты
3. `03_rules.md` — рабочие правила
4. `04_conditions.md` — условия применения протоколов
5. `05_protocols.md` — шаблоны протоколов
6. `06_change_process.md` — процесс гармоничного изменения правил
7. `07_decision_log.md` — журнал решений
8. `08_error_log.md` — журнал ошибок
9. `09_entity_registry.md` — реестр сущностей
10. `10_agent_contract.md` — контракт агента
11. `11_agent_policy.md` — политика агентов
12. `12_agent_handoff.md` — передача задачи между агентами
13. `13_data_sources_map.md` — карта источников данных
14. `14_truth_sources.md` — источники истины
15. `15_input_security.md` — безопасность входящей информации
16. `scope_registry.md` — реестр функций и их статусов

## Законы проекта

Законы имеют наивысший приоритет.

Ключевые законы:

- Закон 1 — сначала факты.
- Закон 2 — не ломать работающее.
- Закон 3 — одна модель истины.
- Закон 4 — безопасность прежде удобства.
- Закон 5 — MVP прежде расширений.
- Закон 6 — каждое изменение проверяемо.
- Закон 7 — прозрачность решений.
- Закон 8 — откат важнее фичи.
- Закон 9 — язык проекта.
- Закон 10 — правила меняются гармонично.
- Закон 11 — статус функции определяет скоуп.
- Закон 12 — разделение источников истины.
- Закон 13 — право отделяется от рекомендации.

## Формат запроса

```text
ПРОТОКОЛ: <тип>
РЕЖИМ: ДИАГНОСТИКА / РЕАЛИЗАЦИЯ / РЕВЬЮ / ПЛАНИРОВАНИЕ
Задача: ...
Сделано: ...
Проблема: ...
Источники: ...
Лог / скриншот: ...
Ограничения: ...
Ожидаемый результат: ...
```

## Формат ответа агента

```text
1. План
2. Действия
3. Проверка
4. Риски
5. Откат
6. Следующий шаг
```

## Статусы правил

- `Proposal` — предложено, обсуждается
- `Agreed` — согласовано, но ещё не внедрено
- `Active` — действует
- `Deprecated` — отменено или заменено

## Статусы функций

Статусы функций фиксируются в `scope_registry.md`:

- `В скоупе` — функция входит в текущий план
- `Вне скоупа` — функция не входит в текущий план, но может вернуться позже
- `Отложено` — функция временно приостановлена
- `Отменено` — функция окончательно исключена

## Источники истины

Источник истины определяется доменом данных согласно Закону 12.

| Тип данных | Основной источник истины |
|---|---|
| Клиент, услуга, запчасть, ресурс, актив, заказ | Ядро «Атмосферы» |
| Проводка, официальный счёт, налоговые данные | 1С клиента |
| Юридическая норма, её текст, редакция и статус | Официальный первоисточник |
| Публичная информация для клиента | Публичный API ядра |
| Действия и подтверждения AI | AI-журналы «Атмосферы» |
| Скоуп и статус функции | `scope_registry.md` |
| Архитектурное решение | `07_decision_log.md` |

## Протоколы

Основные протоколы:

- `ДИАГНОСТИКА` — сбор фактов и поиск причины.
- `РЕАЛИЗАЦИЯ` — безопасное выполнение согласованного изменения.
- `РЕВЬЮ` — независимая проверка изменения.
- `ПЛАНИРОВАНИЕ` — подготовка плана и критериев.
- `ДАННЫЕ` — изменение модели данных.
- `CRM` — работа с EspoCRM.
- `РЕЛИЗ` — подготовка и проверка релиза.
- `ПРАВО` — добавление и обновление юридических норм.
- `КОМПЛАЕНС` — превращение юридической нормы в требование продукта.
- `МИГРАЦИЯ_ДАННЫХ` — безопасная миграция данных из внешней системы.
- `КАТАЛОГ` — работа с услугами и товарами.
- `АКТИВЫ_И_РЕСУРСЫ` — работа с активами, ресурсами и ресурсами клиента.

## Главный принцип

Правила гармоничности и условия изменения правил — см. `06_change_process.md`.

Кратко: правило можно добавить или изменить только если понятна проблема, оно не противоречит законам проекта, понятно как проверять и откатывать, и указан срок пересмотра.

## Проверка перед работой

Перед началом работы над функцией проверьте её статус в `scope_registry.md`:

- если статус «В скоупе» — можно работать;
- если статус «Вне скоупа» / «Отложено» / «Отменено» — сначала согласуйте изменение статуса через реестр.

Статус функции не отменяет законы, запреты и требования безопасности.
