# Процесс изменения правил

Этот файл — канонический источник для:
- правил гармоничности;
- шаблона «ИСКЛЮЧЕНИЕ»;
- формата ответа агента.

Другие файлы (`00_README.md`, `03_rules.md`, `05_protocols.md`) ссылаются сюда.

## Когда можно предложить изменение

Правило можно предложить, если:

- проблема повторилась минимум дважды;
- есть риск потери данных, безопасности или времени;
- текущее правило мешает развитию;
- появился новый обязательный бизнес-сценарий;
- изменились ограничения проекта.

## Формат предложения

```text
ПРЕДЛОЖЕНИЕ ПРАВИЛА
Название: ...
Проблема: ...
Предлагаемое правило: ...
Почему нужно: ...
Как проверить соблюдение: ...
Как откатить: ...
Приоритет: P0 / P1 / P2 / P3
Срок пересмотра: ...
```

## Жизненный цикл правила

```text
Proposal → Agreed → Active → Deprecated
```

| Статус | Значение |
|---|---|
| Proposal | Предложено, обсуждается |
| Agreed | Согласовано, но ещё не внедрено |
| Active | Действует и обязательно к соблюдению |
| Deprecated | Отменено или заменено |

## Условия перевода в Active

- [ ] Понятна проблема.
- [ ] Правило не противоречит законам проекта.
- [ ] Понятно, как его проверять.
- [ ] Понятно, как его откатить.
- [ ] Указан срок пересмотра.
- [ ] Изменение внесено в нужный файл.

## Как отменить правило

```text
ОТМЕНА ПРАВИЛА
Название: ...
Причина отмены: ...
Что заменяет: ...
Дата отмены: ...
```

## Временное исключение

Если правило мешает срочной задаче:

```text
ИСКЛЮЧЕНИЕ
Правило: ...
Задача: ...
Причина: ...
Срок действия: ...
План возврата к правилу: ...
```

Исключение не отменяет правило.

## Правила гармоничности

Новое правило должно:

- решать реальную проблему;
- быть понятным;
- быть проверяемым;
- иметь откат;
- не создавать лишнюю бюрократию.

Если правило не проходит хотя бы одно условие, оно остаётся в статусе `Proposal`.

## Формат ответа агента

Канонический формат ответа агента:

```text
1. План
2. Действия
3. Проверка
4. Риски
5. Откат
6. Следующий шаг
```

## Связь с реестром функций

Изменение статуса функции (добавление/исключение из скоупа, приостановка, отмена) фиксируется в `scope_registry.md` по правилам из `03_rules.md`.
