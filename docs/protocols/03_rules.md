\# Рабочие правила



\## Формат запроса



```text

ПРОТОКОЛ: <тип>

РЕЖИМ: ДИАГНОСТИКА / РЕАЛИЗАЦИЯ / РЕВЬЮ / ПЛАНИРОВАНИЕ

Задача: ...

Сделано: ...

Проблема: ...

Источники: ...

Логи / скриншот: ...

Ограничения: ...

Ожидаемый результат: ...

```



\## Формат ответа агента



```text

1\. Диагноз

2\. План

3\. Действия

4\. Проверка

5\. Риски

6\. Откат

7\. Следующий шаг

```



\## Разделение знаний



Агент обязан разделять:



\- \*\*Факт\*\* — подтверждено логами, файлом, БД, API или командой.

\- \*\*Гипотеза\*\* — предположение, требующее проверки.

\- \*\*Unknown\*\* — информации недостаточно.



\## Уровни уверенности



| Уровень | Значение | Разрешённые действия |

|---|---|---|

| Высокая | Есть воспроизводимое подтверждение | Можно предлагать изменение |

| Средняя | Данные согласуются, но неполны | Только диагностика или безопасная проверка |

| Низкая | Только предположение | Никаких изменений, только план проверки |



\## Приоритеты задач



| Приоритет | Значение |

|---|---|

| P0 | Блокирует запуск или данные |

| P1 | Важно для MVP |

| P2 | Улучшение |

| P3 | Можно отложить |



\## Статусы задач



```text

New → In progress → Review → Done → Deferred

```



\## Минимальный шаг



Один ответ агента может содержать:



\- одну логическую группу изменений;

\- не более 5–10 команд;

\- одну проверяемую гипотезу;

\- один критерий успеха.



Если задача больше — агент делит её на этапы.



\## Definition of Done



Задача считается выполненной, только если:



\- \[ ] Решение применено.

\- \[ ] Проверка пройдена.

\- \[ ] Логи чистые.

\- \[ ] Документация обновлена.

\- \[ ] Решение зафиксировано в журнале.

\- \[ ] Известен план отката.



\## Приоритет при конфликте



1\. Безопасность данных и доступов.

2\. Целостность модели данных.

3\. Работоспособность основного сценария.

4\. Скорость решения.

5\. Удобство и красота решения.
