# Запреты проекта

## Запрещено без явного подтверждения

- Удалять volumes, базы данных или файлы данных.
- Выполнять `docker compose down -v`.
- Менять пароли администратора и API-пользователя.
- Публиковать порты MariaDB и Redis наружу.
- Коммитить `.env`.
- Хранить токены в коде.
- Создавать новых пользователей с правами администратора.

## Запрещено в текущем MVP

- Подключать Telegram.
- Создавать Telegram-уведомления.
- Подключать оплаты.
- Подключать WhatsApp, VK, iiko, Set Prisma, Poster.
- Делать мультиарендность.
- Создавать сложные интеграции до стабильного CRM-контура.

### AI-функциональность

AI-функции не запрещены полностью. Их статус определяется в `scope_registry.md`:

- если функция имеет статус «В скоупе» — работа разрешена;
- если статус «Вне скоупа» / «Отложено» / «Отменено» — работа запрещена до изменения статуса через реестр.

## Запрещено в модели данных

- Создавать дублирующие сущности.
- Хранить одно и то же поле в нескольких местах.
- Использовать свободный текст там, где нужен справочник.
- Создавать поля «на будущее» без бизнес-сценария.
- Менять внутренние имена сущностей после начала работы с данными.

## Запрещено в коде

- Хардкодить секреты.
- Хардкодить URL и порты.
- Использовать `admin` для интеграций.
- Оставлять закомментированный мёртвый код.
- Вносить изменения без понимания текущей архитектуры.

## Запрещено в Git

- Использовать `git add .` без явной просьбы.
- Коммитить временные файлы, логи, дампы и секреты.
- Смешивать документацию, код и инфраструктуру в одном коммите.
- Пушить локальные коммиты без проверки `git log origin/main..HEAD`.

## Исключения

Любое исключение оформляется по каноническому шаблону из `06_change_process.md`.

Кратко: исключение фиксируется с указанием правила, задачи, причины, срока действия и плана возврата к правилу. Исключение не отменяет правило.
