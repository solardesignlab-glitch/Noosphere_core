\# Политика агентов



\## Роли



| Агент | Задача | Доступ |

|---|---|---|

| Координатор | Маршрутизация задач, выбор протокола | Чтение протоколов |

| Аналитик | Анализ, гипотезы, сверка данных | Read-only: БД, логи, файлы |

| Исполнитель | Подготовка и применение изменений | Запись в разрешённые области |

| Ревьюер | Проверка рисков и политики | Чтение diff, логов, протоколов |

| Архивариус | Фиксация решений и ошибок | Запись только в журналы |



\## Принцип минимальных прав



\- Аналитик не меняет код и конфигурацию.

\- Исполнитель не принимает архитектурные решения единолично.

\- Ревьюер не вносит исправления сам.

\- Никто не использует административный доступ к БД без явного подтверждения.



\## Запрещено



\- Давать агентам прямой доступ к production-базе.

\- Менять законы проекта напрямую.

\- Выполнять необратимые команды без подтверждения.

\- Коммитить секреты, `.env`, `chat.json`, токены.

\- Публиковать порты MariaDB и Redis без необходимости.



\## Обязательная сверка



Перед выводом аналитик сверяет гипотезу минимум с двумя источниками:



1\. Реальное состояние системы: БД, логи, API, команда.

2\. Протокол, реестр сущностей или журнал решений.



Если второго источника нет:



```text

Уверенность: низкая

Статус: Unverified

```



\## Конфликт ролей



\- Аналитик не оценивает собственные изменения.

\- Исполнитель не подтверждает собственную работу.

\- Ревьюер не вносит исправления сам.

\- Координатор не отменяет решение ревьюера без зафиксированной причины.



При конфликте решение фиксируется в `07\_decision\_log.md`.
