## 1. Экосистема: четыре уровня владения клиентом

```
01 ОБУЧЕНИЕ  →  02 СЕРВИС  →  03 ПЛАТФОРМА  →  04 ЭКОСИСТЕМА
(контент-план  (делаем за    (подписка:     (CRM полного
+ методология  клиента:      движок +        контура + сайт
ниши, 990–     видео-пакеты, CRM-старт)      + реклама +
2990 ₽)        внедрения)                   аналитика)
```

Сквозная нить всех уровней — **контент-движок** (автоматические субтитры, нарезка, бренд-кит). Он делает ролики для клиентов, для обучения и для собственного маркетинга.

Ключевая защищаемая ценность: **сквозная аналитика «рекламный клик → лид → сделка → оплата → дебиторка»**. Ни агентство, ни CRM-вендор по отдельности этого не дают.

## 2. Продукт: CRM «Управляемая клиентская платформа»

Рабочее название. Позиционирование: «отраслевой конструктор клиентских операций для среднего бизнеса РФ: запуск за 30 дней силами нашей команды внедрения».

### 2.1. Вертикаль №1: услуги с записью
Процесс: лид → квалификация → запись → предоплата → визит → допродажа → NPS → повторная запись → win-back.

Отраслевые сущности: клиент, запись (дата/мастер/услуга), расписание и загрузка мастеров, предоплаты и абонементы, no-show, NPS, услуги и прайс.

Ключевые метрики пилота (база фиксируется до старта):
| Метрика | Цель за 90 дней |
|---|---|
| Лиды без первого касания | −50% |
| Запись → визит (no-show) | −30% |
| Повторные записи | +15% |
| Время управленческой отчётности собственника | ≤15 мин/день |
| Загрузка расписания | +10 п.п. |

### 2.2. Роли и личные кабинеты (ядро видения собственника)
Каждый сотрудник видит кабинет, настроенный под должностную инструкцию:
- **Собственник** — Пульт (раздел 2.4)
- **Администратор/менеджер** — расписание сегодня, записи, подтверждения, чек-лист визита
- **Мастер/исполнитель** — его смена, загрузка, чаевые/рейтинг, задачи
- **Руководитель подразделения** — план-факт своей команды, очередь контроля (записи без подтверждения, просрочки)
- **Бухгалтер/финансист** — счета, оплаты, дебиторка (read-контур из 1С)
- **Кассир** (вертикаль «торговля», позже) — смена, чеки через коннектор к кассовому ПО

Конфигурация кабинетов — через настраиваемые шаблоны ролей (не low-code на старте): набор виджетов, метрик и прав для должности.

### 2.3. Модуль «Мотивация и вовлечение» (геймификация)
- Баллы за действия: первое касание в SLA, подтверждённая запись, оплаченный визит, 100%-заполненная карточка, NPS «5», отработанная жалоба
- Рейтинги внутри отдела, уровни и бейджи, прогресс-бар к плану месяца
- Обмен баллов на награды из фонда мотивации (задаёт руководитель)
- **Анти-гейминг (обязательно):** баллы только за действия, прошедшие контроль качества. Иначе фарм объёма в ущерб качеству
- Геймификация включается ПОСЛЕ ролевых кабинетов, не до

### 2.4. Кабинет собственника (Owner's Cockpit) — премиум-модуль
Дерево: Пульт → Финансы (кэш-флоу 13 недель, управленческий P&L, unit-экономика, дебиторка) → Операции → Активы → Инвестиции → AI-советник → Доступы.

Матрица доступа: финансовый контур видят только собственник + назначенный финансист. Личные активы — только собственник. Полный аудит просмотров.

AI-советник (пилот — 10 вопросов): почему выручка отстала, где маржа, потери от скидок, CAC по каналам, кто проседает, кассовый разрыв, должники, точка безубыточности, прогноз 3 месяца, 3 действия на 30 дней. Формат ответа: вывод → цифры → причина → ссылка на данные. Без цифр ответ невалиден.

### 2.5. Коннекторы (приоритет)
1. **Telegram/VK/WhatsApp** — коммуникации в карточке клиента (первая очередь)
2. **1С:Бухгалтерия 3.0 (типовая)** — контрагенты, счета, оплаты, P&L. Условие отбора пилот-клиентов: типовая конфигурация, без доработок
3. **Банк** — выписки, остатки
4. **Кассовое ПО** (iiko/Set Prisma/Poster) — вертикаль «торговля», фаза 2
5. ЭДО, телефония, рекламные кабинеты — по мере запросов пилотов

## 3. Техническая стратегия под микрокоманду (1–2 разработчика + AI)

### 3.1. Принцип: не пишем ядро с нуля
Собственное ядро CRM = 2+ года до пилота. Стратегия — open-source ядро + собственные модули отличия.

| Кандидат | Плюсы | Минусы | Вердикт |
|---|---|---|---|
| **EspoCRM** (PHP, open source) | Лёгкий, быстрый, модульная архитектура, русскоязычное сообщество, дешёвый хостинг | PHP-стек, UI требует адаптации | **Рекомендация для старта** |
| Twenty (TypeScript) | Современный стек, красивый код | Англоязычное ядро, меньше зрелости, тяжелее кастомизация ролей | Альтернатива, если команда сильна в TS |
| SuiteCRM | Функционально богатый | Тяжёлый, дорогая кастомизация, устаревший UX | Нет |

Собственная разработка: кабинет собственника, модуль мотивации, вертикальные пакеты, коннекторы, AI-слой.

### 3.2. Распределение ролей
- **Разработчик №1 (архитектор, фулстек)** — ядро, интеграции, деплой, инциденты. Необходим с первого дня
- **Разработчик №2** — фазы 1–2, модули, фронт кабинетов
- **AI-ассистент** — генерация кода и ТЗ, аналитика, документация, подготовка интервью, ревью решений. Ускоритель ×2–3, не замена прод-ответственности
- **Отраслевой методолог** — вы (собственник) + первые пилот-клиенты: процессы, должностные инструкции, метрики

### 3.3. Юридическая рамка РФ
- 152-ФЗ: хостинг в РФ (Yandex Cloud / Selectel), регистрация оператора ПДн, согласия в формах
- 38-ФЗ «О рекламе»: рассылки только с согласия, метка «реклама»
- 54-ФЗ: фискализацию НЕ берём на себя (коннектор к кассовому ПО)
- AI-граница: информационно-аналитический инструмент; по ценным бумагам — только факты; решения принимает собственник
- Цель на горизонте 12 мес: реестр российского ПО (ускоряет госсектор и enterprise-продажи)

## 4. Контент-движок и сайт

**Контент-движок** (первый продукт экосистемы, даёт деньги с месяца 1–2): ядро из WhisperX (таймстемпы слов) + пофреймовый рендер подсветки (4 суб-стиля: цвет/масштаб/фон/прыжок) + ffmpeg burn-in. Продукт: пакеты 20–30 роликов/мес для клиентов агентства.

**Сайт** — два контура:
1. Маркетинговый (сейчас): нишевые SEO-страницы («CRM для салонов красоты», «CRM для автосервисов»), формы заявок → CRM (UTM + чекбоксы 152-ФЗ), кейсы пилотов
2. С месяца 6–9: перенос на собственное ядро (headless) — CRM продаёт себя через сайт на самой себе, сквозная аналитика клик→деньги

## 5. Дорожная карта 24 месяца (микрокоманда)

### Фаза 0 · Месяцы 1–3 — «Деньги и ядро»
- Контент-движок: MVP (субтитры, 3 стиля, 1 клиент-пилот из текущей базы)
- CRM: развёртывание EspoCRM, адаптация под «услуги с записью», Telegram-канал, кабинет администратора, карточка клиента + запись
- 10 глубинных интервью с собственниками услуг (скрипт — отдельный файл)
- 3 пилот-клиента CRM на **ручной настройке** (фикс 150–250 тыс. ₽), обязательное условие: типовая 1С Бухгалтерия 3.0

### Фаза 1 · Месяцы 4–9 — «Вертикаль и собственник»
- Ролевые кабинеты (мастер, руководитель, финансист), модуль мотивации
- Кабинет собственника: Пульт, кэш-флоу 13 недель, P&L план-факт, дебиторка
- Коннектор 1С (типовая Бухгалтерия 3.0) + банк
- AI-чат-аналитик (10 пилотных вопросов) + еженедельный дайджест
- SaaS-тарификация, мультитенантность
- **Веха самоокупаемости: пилоты + подписки покрывают ФОТ команды (цель — месяц 6–9)**

### Фаза 2 · Месяцы 10–18 — «Платформа»
- Сайт на собственном ядре, личный кабинет клиента SaaS self-service
- Коннектор кассового ПО, вертикаль «торговля» (первые кассиры)
- Вертикаль №2 (стройка/ремонт — по запросам)
- Инвестиционный модуль, стресс-тесты

### Фаза 3 · Месяцы 19–24 — «Enterprise-опции»
- On-premise предложение (первый клиент платит — делаем)
- Реестр российского ПО, ФСТЭК-траектория
- Партнёрская академия интеграторов

### Критерии успеха MVP (зафиксированы)
- 10 платящих пилотов в вертикали «услуги»
- Средний срок запуска ≤30 дней (силами команды внедрения)
- Churn 6 мес < 5% · NPS > 40 · ROI-кейс у ≥5 клиентов
- Месячная выручка подписок + сервиса ≥ ФОТ команды проекта

## 7. Главные риски и ответы

| Риск | Ответ |
|---|---|
| 1–2 разработчика — узкое горло | Open-source ядро, жёсткий приоритет фич (правило: «нет» по умолчанию), AI-ускорение |
| Коннектор 1С затянется | Пилоты только на типовой Бухгалтерии 3.0; нестандарт — в проектную стоимость |
| Обещание «30 дней» не сдержать | «30 дней силами команды внедрения» — ручная донастройка входит в фикс |
| AI-ответственность | Информационно-аналитический инструмент, сценарии вместо советов, договорные оговорки |
| Универсальность убьёт фокус | Вертикаль «услуги» до результата; новые ниши — только после 10+ кейсов в текущей |
